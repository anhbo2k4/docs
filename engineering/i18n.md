# Internationalisation (i18n)

**Status:** Active
**Owner:** Mobile Lead + PO

## Scope at MVP

- App ships in **English** and **Vietnamese**. Other locales post-MVP.
- Backend error messages return `error_code` (stable, English UPPER_SNAKE) and an optional `message` (English). Mobile maps to localised user-facing copy.
- Documentation language: English (per AGENTS.md). Conversational comments in Vietnamese tolerated in `traceability/decision-log.md` only.

## Mobile

- Use `flutter_localizations` + ARB files under `mobile/lib/resource/l10n/`.
- ARB filenames: `intl_en.arb`, `intl_vi.arb`.
- Keys are `screen.feature.element_purpose`, e.g. `auth.otp.button_send`.
- One key per logical message; no concatenation of fragments at runtime.
- Plurals: ARB ICU MessageFormat. Never hand-roll plurals in Dart.
- Numbers, dates, currencies via `intl` package, not string templates.
- Right-to-left: Flutter handles automatically; designers must verify mirrored layouts as locales expand.

## Workflow

1. Engineer adds the English string to `intl_en.arb` with `@key` metadata (description, placeholders).
2. CI runs `flutter gen-l10n`; lint fails if any key in `intl_en.arb` is missing in `intl_vi.arb`.
3. PO or designated translator fills `intl_vi.arb`; PR reviewer checks domain accuracy.
4. Strings used only by analytics / logs are NOT localised (those are L1 internal — see `security/data-classification.md`).

## Number / date formats

- Time: 24-hour for VN locale by default; 12-hour for en-US (none in MVP).
- Date: ISO `yyyy-MM-dd` in all logs and exports; user-facing format follows locale.
- Numbers: locale-aware separators via `intl`.

## What must be localised at MVP

- All user-visible UI in: auth, shifts, capture, sync center, error states.
- Push notifications.
- Email templates (post-MVP, scope-pending).

## What is NOT localised at MVP

- Logs, metrics, internal admin endpoints.
- Error codes (only the human message is localised).
- Onboarding videos / images (English voiceover with subtitles if produced).

## Backend

- Error responses include `error_code` + English `message` + optional `params`.
- `Accept-Language` honored only as a hint; the canonical contract is the code.
- Mobile renders the localised string from a code → string table:
  ```dart
  String l10nFor(String code) => switch (code) {
        'OTP_EXPIRED' => l10n.auth_error_otp_expired,
        'EMPLOYEE_NOT_MAPPED' => l10n.auth_error_not_mapped,
        _ => l10n.error_generic,
      };
  ```

## Testing

- Golden tests snapshot key screens in both locales.
- Dynamic-type tests at 200 % verify VN text doesn't truncate (TC-A11Y-003).
- A spot-check checklist in `qa/test-cases.md` (A11Y) covers locale switches.

## Pseudolocalisation (planned)

- Add `intl_xx.arb` with bracketed expanded variants (`[!! ééxxààmppllée!!]`) before adding a 3rd real locale.
- Catches truncation, hard-coded strings, concatenations.

## Adding a new locale (post-MVP runbook)

1. Add `intl_<lang>.arb`.
2. Run `flutter gen-l10n`.
3. Update store metadata in that locale.
4. Add a row in the device matrix smoke test for that locale's primary device.
5. Translate, review, ship behind feature flag `i18n.<lang>.enabled` until rollout.
