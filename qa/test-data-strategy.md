# Test Data Strategy

**Status:** Active
**Owner:** QA Lead + Backend Lead
**Last updated:** 2026-05-13

This document defines how realistic, safe, repeatable test data is produced and used across unit, integration, e2e, performance, and pilot environments.

---

## 1. Goals

- Tests reproducible: same fixtures for unit + integration + e2e + perf.
- Pilot-realistic: fixtures resemble real Odoo objects (project, task, planning slot) with realistic distributions.
- Safe: no production PII ever in test environments.
- Versioned: fixtures change deliberately, with a CHANGELOG entry.

---

## 2. Layers

| Layer | Source | Use |
|---|---|---|
| Unit fixtures | `mobile/test/fixtures/` and `backend/tests/fixtures/` | Per-test, in-process |
| Integration fixtures | `tests/integration/seeds/` | testcontainers Postgres + mock Odoo |
| E2E datasets | `tests/e2e/datasets/` | patrol_cli + mocked backend |
| Performance corpora | `tests/perf/corpora/` | k6 / locust scenarios from `qa/load-plan.md` |
| Pilot seed | `tools/seed-pilot/` | Curated dataset deployed to pilot Odoo + Postgres pre-launch |

## 3. Personas (anonymised, deterministic)

| Persona | Role | Phone (E.164, regional pilot range) | Notes |
|---|---|---|---|
| `P-001` | Field Worker A | +84-900-000-001 | Active worker, 5 shifts queued |
| `P-002` | Field Worker B | +84-900-000-002 | Edge case: just hired, no shifts |
| `P-003` | Field Worker C | +84-900-000-003 | Edge case: long-tenure, lots of evidence |
| `P-100` | Supervisor A | +84-900-000-100 | Approves PPE, reviews work results |
| `P-200` | Admin A | +84-900-000-200 | ERP admin (web only) |
| `P-999` | App-Review | +84-900-000-999 | Magic OTP (`runbooks/otp-fallback.md`) — for store reviewers |

Phones are dedicated, not real numbers. SMS provider config maps the prefix `+84-900-000-` to a sink that returns the magic OTP.

Names: Latin + Vietnamese diacritics mix, e.g. "Nguyễn Văn A", "Trần Thị B" — to exercise i18n (`engineering/i18n.md`).

## 4. Shift / project corpus

Generated by `tools/seed-corpus/build_shifts.py`. Inputs: number of workers, shifts per worker, date range, distribution profile.

Distributions used in tests:

| Profile | Workers | Shifts/worker | Date range | Used by |
|---|---|---|---|---|
| `tiny` | 3 | 5 | last 7 days | Unit + most integration tests |
| `small` | 25 | 20 | last 30 days | E2E full-flow |
| `pilot` | 50 | 30 | last 90 days | Performance LP-001..008 |
| `xlarge` | 5000 | 100 | last 365 days | Capacity / soak only |

Corpora are deterministic given a seed. The seed is committed in the corpus manifest.

---

## 5. Evidence corpus (photos, audio)

- Photos: 30 generated images from a checked-in template (no real photos). Sizes deliberately span 200 KB → 5 MB to test compression (PB-M-007).
- Audio: 20 generated WAV files (silence + tone + tone-with-spike) of 3, 30, 90, 180, 600 seconds — to exercise Whisper boundaries.
- File names: `evidence-<persona>-<index>.<ext>`. EXIF stripped before commit (per `security/data-classification.md` rule).

Generation tool: `tools/seed-evidence/generate.py`. Run manually; outputs are cached and not regenerated unless seed changes.

---

## 6. Sync envelope corpus

Generated by `tools/seed-corpus/build_envelopes.py`. Produces:

- `envelopes-clean.jsonl` — happy-path
- `envelopes-conflict.jsonl` — same `client_id`, different payload (force 409 path)
- `envelopes-stale.jsonl` — created 30 days ago (exercise retention)
- `envelopes-corrupt.jsonl` — JSON shape invalid (validate dead-letter)

Each line in JSONL is an envelope per `api-contracts/sync.md`.

---

## 7. Anonymisation rules (when real data is touched)

If a defect requires looking at real captures (after consent):

1. Pull only the minimum needed.
2. Pass through `tools/anonymise/scrub.py`:
   - Phone → bucketed prefix + random suffix.
   - GPS → snap to 100 m grid (privacy preserved, regional pattern kept).
   - Photos → blur faces + license plates via on-device model; strip EXIF.
   - Names → faker-replace with deterministic seed.
3. Store under `tests/forensic/<incident>-<date>/`. Auto-delete after 90 days.

This applies during postmortems (`runbooks/_postmortem-template.md`).

---

## 8. CI integration

- `pr-backend.yml` integration tests load `seeds/integration.sql` against testcontainers Postgres.
- `pr-mobile.yml` golden tests load `mobile/test/fixtures/golden_data.json`.
- `nightly-soak.yml` boots the `pilot` profile against a dedicated environment.
- Fixture drift: a hash of the seed scripts is compared against the lockfile `tests/fixtures.lock`. If they diverge without an entry in CHANGELOG, CI fails.

---

## 9. Pilot seeding

Before pilot launch (`qa/pilot-gate.md` checklist):

1. Run `tools/seed-pilot/apply.py --env pilot --profile pilot` against pilot Odoo + Postgres.
2. Verify 50 workers + 1500 shifts visible to the pilot supervisor.
3. Smoke test: log in as P-001, capture 1 PPE, sync, see entry in Odoo within 30 s.
4. Document the seed run in `WORKING.md` under "Last decisions".

The pilot environment is wiped and reseeded per release cycle; no real customer data is added until production cutover.

---

## 10. Forbidden patterns

- Hard-coding real phone numbers.
- Copy-pasting production exports into the repo.
- Photos with real people unless you have written consent and have run the anonymiser.
- Using the same corpus seed for happy-path and edge-case tests (defeats the purpose).
